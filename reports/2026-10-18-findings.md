# Reproduced Rialo integration findings — 18 October 2026

Environment: Node.js 22.22.0, official `@rialo/ts-cdk@0.18.1`, public Devnet RPC. No private docs, logged-in sessions or hidden APIs are required to reproduce these observations.

## 1. Real transaction succeeds; SDK receipt parser fails

A single system-account creation executed at block **2775152**. The RPC reports `meta.err: null`, fee **0 kelvin**, and **150** compute units. The resulting zero-data account exists with the System Program as owner.

- [Transaction](https://rialo-explorer-devnet-direct.vercel.app/txs/5UD6CupQHvQhKzNuLszdxyvwjijtHsv3ZnM6oN5JBSgswGMhsxen9LTT5omXc48v8DA9Kvn47PsDh9B9WxkFKBSc)
- [Created account](https://rialo-explorer-devnet-direct.vercel.app/accounts/4FiCKXU3vvvi4eRuoHVqLubDMfHrZfqgCouNjSo7szUC)
- [Recorded public RPC response](../tests/fixtures/canary-rpc.json)

One faucet request funded 100,000,000 test kelvin (0.1 test RLO). Account rent was 890,880 kelvin; the remaining payer balance was 99,109,120 kelvin. No mainnet funds were used and no trading or betting occurred.

Calling `client.getTransaction(Signature.fromString(signature).toBytes())` against that transaction throws:

```text
TypeError: Cannot read properties of undefined (reading 'map')
QueryRpcClient.getTransactionDetails
```

The SDK reads `result.transaction.message.account_keys`; the actual RPC (`0.22.0-alpha.2`) returns `accountKeys`. Nested header fields, `programIdIndex`, `validFrom` and log fields also differ in casing. This is a client/node schema compatibility issue; it does not mean the transaction failed.

**Provided fix:** [`src/receipt.mjs`](../src/receipt.mjs) accepts both field conventions, checks transaction identity, rejects incomplete responses and unsafe integer conversion, and returns a normalized receipt. [`tests/receipt.test.mjs`](../tests/receipt.test.mjs) reproduces the stock SDK failure using the captured response and validates the adapter without spending test tokens again.

Reproduce:

```sh
npm ci --ignore-scripts
npm test
```

Live read-only check:

```js
import {getReceipt} from './src/receipt.mjs';
const receipt = await getReceipt('https://devnet.rialo.io:4101',
  '5UD6CupQHvQhKzNuLszdxyvwjijtHsv3ZnM6oN5JBSgswGMhsxen9LTT5omXc48v8DA9Kvn47PsDh9B9WxkFKBSc');
console.log(receipt);
```

Additional integration details: the `RialoClient` wrapper returns raw signature bytes from `sendTransaction` and `requestAirdrop`; use `Signature.fromBytes(bytes).toString()` for base58. `SYSTEM_PROGRAM_ID` is a string; convert it with `PublicKey.fromString()` where an instruction helper expects a `PublicKey`.

## 2. ERMAC's configured programs are absent on inspected public networks

Source: [official ERMAC app](https://ermac.rialo.io/), public helper [frost-public-key-tgtsfZiz.js](https://ermac.rialo.io/assets/frost-public-key-tgtsfZiz.js). The app selects Devnet with `https://devnet.rialo.io` as its RPC.

| Dependency | Configured address |
|---|---|
| Median aggregator | `M4tvfJkVtzhBozkywmG45xfvBJhVqJghqSuxjEKY6Mx` |
| Feed registry | `3nmnQVAgKaBrWiauqdEwoSqa8rVACjEbZVcGH5VeVn62` |
| Subscriber | `95uDFDmcDHB32zpBzfaaXhmVNeJ5PAt2FaFw4nPknuho` |
| Global index PDA | `3UBDAjfooL8e64tTRtJAgP9RXj15qfZx1TZ2faLKz35y` |

All four returned “Account does not exist” through the SDK on Devnet HTTPS 443, Devnet port 4101 and Testnet port 4101. Health and block-height calls succeeded; the System Program existed. These are distinct from a timeout or inaccessible docs. A network reset or deployment/configuration mismatch is possible, but the cause is not established.

The runner verifies this prerequisite every 15 minutes. It deliberately does not initialize the shared global registry or send a feed transaction to missing programs. Its standalone feed serializer was compared against the official frontend helper with the same timestamp, config hash and deterministic slug: all **736 unsigned bytes** matched. This proves wire compatibility with the inspected app version, not successful live feed execution.

## 3. Bounded workaround

The monitor reads the official public SDK and RPC directly. It does not need to bypass Cloudflare Access or browser wallet UI. The adapter resolves the observed transaction-query incompatibility. Automatic feed creation remains conditional on executable programs, correct registry ownership, an unchanged pinned public app asset, one configured Devnet wallet, bounded faucet/fees and a persistent no-duplicate submission journal.

The code and evidence are public for review. No maintainer acceptance, official contribution credit, new points or token allocation has been confirmed.
